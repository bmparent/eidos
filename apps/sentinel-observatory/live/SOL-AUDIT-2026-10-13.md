## Audit repairs and validation

Incoming observation bodies now have a two-second deadline and a 1,024-byte limit. Stalled/cancellation streams cannot delay their rejection; oversized input has correct request wording and HTTP 413. Sensor security-control rows require the actual expected enforcement status; authentic legacy HTTP 400 oversized-request records remain resolvable.

First-hop HEAD response latency now includes valid redirect receipts. Redirect/non-redirect or collector-identity transitions reset detector and forecast calibration, including clock changes between vantages. Error, TLS-failure and unattempted requests remain excluded. HTTP 304 is no longer described as a redirect. Canonical Sentinel math is unchanged.

Sol work uses durable per-evidence deduplication, atomic reservations, a 60-second cooldown, 20-request guard and $0.50 UTC daily reservation ceiling. At $0.05 per reservation this permits at most 10 new provider attempts daily. Failed or uncertain attempts remain reserved; no automatic retry occurs. Model jobs expire after eight days on the next valid retained-evidence interpretation request. These are conservative application controls, not a billing invoice or provider account cap.

The provider boundary binds the runtime fetch receiver, uses manual redirect handling without forwarding keys, validates returned model/response/usage identity, propagates cancellation and rejects malformed or unverified output. Cache reads revalidate catalogue choices and rebuild facts from authoritative metadata. UI provenance distinguishes verified execution, accepted output, uncertain attempts and missing-key fallback. Unrelated framing is blocked while intended ChatGPT framing remains allowed.
