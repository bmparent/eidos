# Actual compiled Next versus browser ZIP

This receipt compares the raw approved package created by the built Vite browser with the actual optimized Next route module. It deliberately avoids a TypeScript loader, so it tests compiler output rather than a second copy of the source-level fixture.

From the backend repository root, after the source build:

```text
npm --prefix apps/sentinel-lab run build
node artifacts/playground-unified-backend-20261014/delivery/compiled-browser-parity/probe.cjs artifacts/playground-unified-backend-20261014/delivery/compiled-browser-parity/browser-approved.zip --require-match
```

The probe locates the compiled delivery module from the actual route, blocks outbound fetch, freezes SNAPSHOT.json in a real in-memory SQLite database, reads back the immutable archive and requires all ZIP bytes to match. Outputs go to ignored `apps/sentinel-lab/.vercel/compiled-delivery-check/`; the retained receipt here is not overwritten. No hosted database, provider, payment or mail is involved.

The retained input was generated by Chromium against the production Vite preview. The package includes an uploaded image. Both input and output contain 128,347 bytes with SHA256 `3f1b0c20f676a51126af4faa6207a6f90c8f0dda2af5d2b09d1f18699846fe71`. The observed script parses without an injected `__name` helper. Separate six-engine/width execution evidence is retained under `../compiled-runtime-after/browser/`.

This is a source-specific historical receipt. A subsequent source change must generate a fresh browser input and a fresh receipt; changed exported CSS may legitimately change a new package. Stored purchased archives continue to be read as their original immutable bytes.
