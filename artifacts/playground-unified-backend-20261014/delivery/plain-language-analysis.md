# Delivery backend source gate

Installed only the explicit frozen-project graph under lib/works/project-delivery, with a small renderer adapter. The legacy schema-1 vendor model and renderer were not replaced. The source exporter hashes and writes UTF-8 LF text; .gitattributes preserves that representation on Windows and Linux. The backend test checks the actual file inventory and adapter hash.

The authenticated relay now routes GET/POST /api/playground/delivery with a 1,520,000-byte request ceiling and off-by-default EIDOS_PLAYGROUND_DELIVERY_MODE. Controlled real libSQL tests prove one immutable record under four retries, owner isolation, exact ZIP bytes/hash, missing-mode refusal, both canonical production host refusals and preservation of the legacy schema-5 HTTP 409 boundary. Two independent connections cannot exceed an owner's quota, and a chunk insertion fault rolls back the whole archive. No provider or asset fetch is permitted during this fixture.

The final mirrored order hooks preserve the original archive download and add an explicit approved-page selector. That selector requires the bound signed-in owner, paid TEST order, no refund/revocation and exact stored hashes. Snapshot ownership alone is not payment authority. Checkout binds the approved snapshot and actual verified parent archive before creating an external session. Shared cap/merchant logic remains unchanged. Review detail is in order-hook-review.md.

The authoritative frontend server suites passed 37 controlled tests; their receipt/log are retained alongside the backend results. Typecheck passed. A first delivery fixture forced schema 5 onto a schema 1 object without upgrading section identities; the corrected fixture uses the accepted upgrade helper and the failed run is retained. Final graph/build results are recorded separately in final-source.json.
